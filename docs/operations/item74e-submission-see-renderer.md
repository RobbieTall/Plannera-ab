## Purpose

This renderer creates real deterministic DOCX and PDF bytes from an accepted submission SEE candidate without weakening the existing evidence/finality boundary.

The renderer is a presentation layer only. It does not decide planning outcomes, add uncited content or turn a working/blocked candidate into a submission-ready one.

## Final-render boundary

Rendering refuses a candidate unless the existing submission acceptance gate is green when only the not-yet-created outputs are represented by internal placeholders.

Final rendering therefore still requires:

- A$749 submission product identity;
- Preview or test mode, never Production;
- exact confirmed-site ID and address fingerprint;
- verified authoritative spatial evidence;
- current DPP/QSC chain;
- complete cited canonical sections;
- ready, indexed and section-bound upload evidence;
- no non-final declaration; and
- approved versioned operator review with no unresolved issues.

The placeholders never leave the preflight call. Real output metadata is calculated only from the generated bytes.

## Working-render boundary

The separate working renderer remains visibly non-final and may tolerate only the existing named evidence/readiness blockers. It still rejects identity, provenance, scope, A$749 product/price, source, citation, section, output-integrity and Production-commercial-mode faults.

Every working output must remain visibly marked:

`WORKING SEE - NOT SUBMISSION READY`

and must carry the persisted outstanding-evidence schedule and DPP lineage.

## Shared presentation model

DOCX and PDF consume one deterministic presentation model so the two formats cannot silently drift in:

- section numbering;
- site/status wording;
- document-control values;
- source/evidence labels;
- outstanding-evidence schedule;
- limitations.

## DOCX

The DOCX renderer creates an OOXML ZIP package containing:

- content types and package relationships;
- core and application properties;
- a professional Plannera cover;
- document-control page;
- static numbered contents;
- canonical numbered section hierarchy;
- proposal summary and document-status callout;
- per-section evidence-used callouts;
- working outstanding-evidence table where applicable;
- supporting-evidence schedule;
- source-register table;
- limitations treatment;
- restrained header/footer and page numbering;
- explicit relationship from `word/document.xml.rels` to `word/styles.xml`.

The archive is deterministic and uses stored ZIP entries with CRC-32 checksums.

### DOCX regression note

Visual QA exposed a material defect where `styles.xml` existed in the package but was not related from `document.xml.rels`. Word-compatible rendering therefore collapsed intended pagination and typography despite apparently valid XML.

The renderer now emits the styles relationship explicitly, unit coverage requires it, and the accepted synthetic DOCX renders to 14 A4 pages.

## PDF

The dependency-free PDF renderer creates:

- professional branded cover;
- document-control page;
- numbered contents;
- one deliberate page per canonical assessment section;
- evidence callouts/cards;
- supporting-evidence schedule;
- source register;
- limitations pages;
- consistent header/footer/page numbering;
- deterministic cross-reference table.

The PDF uses built-in Helvetica/Helvetica-Bold with the existing conservative WinAnsi/transliteration boundary. No unapproved font dependency was added.
