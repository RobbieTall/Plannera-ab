# Item 74E submission SEE output rendering

Status: **DETERMINISTIC RENDERER + REFERENCE-INFORMED FRONT MATTER IMPLEMENTED / HOSTED VISUAL ACCEPTANCE NOT EXECUTED**

## Purpose

This renderer creates real DOCX and PDF bytes for an accepted submission SEE
candidate without adding document-generation dependencies.

## Final-render boundary

Rendering refuses a candidate unless the existing acceptance gate is green
when only the not-yet-created outputs are represented by internal placeholders.
This means rendering still requires:

- A$749 submission product identity;
- Preview or test mode, never Production;
- exact confirmed-site ID and address fingerprint;
- verified spatial evidence;
- current DPP/QSC chain;
- complete cited sections;
- ready, indexed and section-bound uploads;
- no non-final declaration; and
- approved versioned operator review with no unresolved issues.

The placeholders never leave the preflight call. Real output metadata is
calculated only from the generated bytes.

## DOCX

The DOCX renderer creates an OOXML ZIP package containing:

- content types and relationships;
- core and application properties;
- styled cover/front matter;
- a real Word TOC field marked dirty for refresh on open, with deterministic fallback entries;
- Word update-fields settings plus a dedicated contents page;
- a page break before the first substantive section;
- page-sized section layout;
- headings and body text;
- per-section source summaries;
- source register;
- limitations; and
- page-number footer.

The archive is deterministic and uses stored ZIP entries with CRC-32 checksums.
DOCX preserves Unicode source text.

## PDF

The PDF renderer creates:

- A4 paginated pages;
- styled cover page;
- a deterministic contents page with section/page references derived from the actual layout pass;
- section headings and wrapped body text;
- per-section source summaries;
- source register;
- limitations;
- page numbers; and
- a deterministic cross-reference table.

The dependency-free PDF uses the built-in Helvetica/WinAnsi font boundary.
Characters outside that encoding are conservatively transliterated or replaced
rather than embedded with an unapproved font dependency. Visual acceptance must
confirm this is adequate for Byron and Kempsey customer data before launch.

## Output evidence

For each file the renderer returns:

- exact MIME type;
- privacy-safe filename derived from confirmed-site ID;
- SHA-256 content hash;
- byte length; and
- generation timestamp.

The tests feed that metadata back into the submission acceptance gate and
require the candidate to become ready.

Issue #431 aligns front matter with recurring conventions in the user-approved

## Current limitations

This slice does not persist files, expose a download route, render a real
customer project, verify final pagination/TOC refresh in Microsoft Word or PDF
appearance in Adobe Reader/Preview, lay out real maps/tables/figures, or complete
operator acceptance. Those require protected hosted Preview generation and
human visual review against the approved reference library.

## Safety

- Production checkout remains disabled.
- Rendering is pure and performs no database writes.
- No new package dependency is introduced.
- No Production schema, data or configuration is changed.
- Production mode and unapproved review are rejected before rendering.
- CI fixtures contain no real address, parcel, coordinate, credential or
  uploaded customer content.
