## Synthetic quarantine flight

The first hosted flight uses a generated byte sequence with no address,
filename, parcel, coordinate, proposal measurement or user content.

It must prove:

- unauthenticated, cross-project, disabled and Production requests write
  nothing;
- the accepted request writes exactly one opaque private object;
- unauthenticated direct access cannot retrieve the object;
- authenticated server retrieval returns the same SHA-256 content;
- the customer-facing result contains no Blob host, direct URL, object
  reference, owner reference or raw content;
- the object remains `QUARANTINED`;
- scanner-unavailable and review-pending states cannot become accepted
  evidence;
- A$49, A$749 and Production checkout eligibility remain false;
- replay does not create a second object;
- cleanup deletes the object and any synthetic metadata;
- post-cleanup reconciliation reports zero residual synthetic objects and rows.

This first flight does not fabricate a `CLEAN` malware result. A real scanner
and operator-review queue must be accepted separately before a document can
enter the evidence-confirmed package.

## Rollback

If any check is red or environment scope is uncertain:

1. keep or restore `ITEM74H_PRIVATE_EVIDENCE_UPLOAD_ENABLED=false`;
2. delete the synthetic private object;
3. remove the branch-scoped temporary activation variable;
4. remove any Preview-only credential connection if it is unsafe;
5. delete the new store if it is dedicated to this failed flight and no object
   remains;
6. redeploy the clean exact branch head;
7. confirm the coordinator returns `FEATURE_DISABLED`;
8. record only aggregate cleanup evidence in PR #347.

Never print a secret while diagnosing or proving rollback.
