# Live User Pilot — 41 Julian Rocks Drive, Byron Bay

Status: Candidate real-user pilot; not yet a validated golden case  
User: Sean  
Last updated: September 2026

## Purpose

Use 41 Julian Rocks Drive as a real-user Plannera pilot to test the actual customer workflow with real project documents and direct user feedback.

This is not a synthetic acceptance fixture and must not become an authoritative planning precedent merely because it is useful for testing.

## Current evidence in Drive

The project folder currently contains:

- 251107 Design Intent - Julian Rocks Dr (1).pdf
- 251107 Landscape Drawings - 41 Julian Rocks Dr (1).pdf

Preliminary extraction indicates the material includes rebuilt/extended decks, an entertaining pavilion with skillion roof, spa, gym area under deck, outdoor shower/privacy screening, bin-store screening, new concrete slab, paving, retaining/seat walls, landscape works, an existing sewer line, tree removals, planting and lighting.

These are preliminary document-derived observations only. They must be reconciled with the complete proposal, current survey/site evidence, statutory sources and any later documents supplied by Sean.

## What this pilot should test

- ingest real customer plans and preserve provenance;
- distinguish plan evidence from user-provided statements and model inference;
- extract a usable proposed-works summary without forcing the user to retype the project;
- let the user confirm/correct that extracted proposal before it becomes the active scope;
- combine plans with current LEP, DCP, SEPP and spatial evidence;
- identify missing evidence and ask only material follow-up questions;
- detect relevant landscape, tree-removal, sewer, setback and built-form issues without inventing triggers;
- maintain the exact project/site/proposal/evidence chain through Quick Site Check, Planning Controls Pack, feasibility/delivery planning and SEE generation;
- regenerate affected outputs as evidence improves;
- apply the canonical flexible SEE standard at a proportionate residential scale;
- collect direct user feedback on usefulness, clarity, omissions and friction.

## Validation boundary

Do not hard-code site-specific findings into Byron rules.

Any reusable learning from this project must be classified as one of:

1. current authoritative statutory/spatial rule;
2. validated professional assessment pattern; or
3. practitioner/user workflow heuristic.

Before this case becomes a formal golden case, expected planning outcomes should be independently reviewed by an appropriately experienced planner against the current evidence and controls.

## Recommended pilot sequence

1. Establish current authoritative site/planning/spatial baseline.
2. Ingest design-intent and landscape plans.
3. Generate a provenance-backed proposed-works summary.
4. Have Sean confirm/correct the proposal.
5. Run the normal Plannera planning-controls workflow.
6. Identify genuinely triggered missing evidence or professional inputs.
7. Generate a working SEE using the canonical SEE Builder standard.
8. Compare output against experienced-planner review.
9. Capture Sean's feedback.
10. Separate product lessons from site-specific planning conclusions.

## Commercialisation sequencing

This pilot must not displace the current commercialisation-critical work. It should become a realistic live-user acceptance case once the durable same-project commercial/evidence workflow is ready to test with a genuine customer project.

## Success signal

Sean can review what Plannera extracted from his documents, correct it where necessary, understand the planning position and remaining inputs, receive a proportionate working SEE, and provide useful feedback without hidden manual reconstruction of the project.
